Architect altitude (student optimises React at work → syntax skipped; whole session = *when optimising is worth it* + English articulation). Module 06 teaching now complete.** Frame: **React's default is fast; optimisation is a cost, not a free win.** Four concepts. (1) **Measure first** — a re-render is a function call + diff, *not* a repaint; every memo primitive costs memory + comparison work, and `useMemo`/`useCallback` add a **new correctness surface** (the deps array) — a bug class you volunteered for. Profile → fix the one proven hot path → leave the rest simple. (2) **`memo` + `useCallback`/`useMemo` are one system: referential stability** — memo compares props by reference, so an inline `onClick={() => …}`, `style={{}}` or `data={filter()}` **defeats it**, and a defeated memo is pure overhead; the architectural consequence = *you cannot memoise a component in isolation* — memoising the child obliges stabilisation on everything upstream (a coupling you bought). (3) **The best re-render fix is structural, not memo** — colocate state (push it down so fewer components sit under the change) and lift the heavy child up to pass as `children` (created in the grandparent's render, so the parent's own state change doesn't touch it); memo treats the symptom, moving state treats the disease. (4) **Code splitting is a different axis** — `React.lazy` + `<Suspense>` targets bundle size / time-to-interactive, not render speed; split where the user won't feel the gap (routes, modals, below-the-fold) and the code is genuinely heavy (charts, editors, map SDKs); two cliffs = too granular → request waterfall, too coarse → nothing gained. Also: pagination/virtualization beats memoising 10,000 rows. **Q1 (objection to a memo-everything PR):** solid unaided on both halves (per-use cost → only where profiling proves it; deps arrays = stale-state risk). **One precision correction: `React.memo` has no dependency array** — that's `useMemo`/`useCallback`; memo's cost is comparison + coupling, theirs is correctness.
