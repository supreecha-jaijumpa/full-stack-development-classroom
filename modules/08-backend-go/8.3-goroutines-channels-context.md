# 8.3 Goroutines, Channels & Context

> Module 08 — Backend with Go · Phase 3

**What you'll learn:** How Go runs many things at once, how that differs from the Node event loop, and how to avoid the bugs that come with it.

- Goroutines and the runtime scheduler vs. one JS thread and an event loop
- Why a blocking call stops one goroutine, not the whole server
- Channels, `select`, `sync.WaitGroup`, and `sync.Mutex`: when to use each
- Data races, and finding them with the race detector (`-race`)
- `context.Context`: cancellation and timeouts passed through a request
- Goroutine leaks, and CPU-bound work running across multiple cores

**Hands-on:** Build a concurrent URL checker with a limited worker pool, a timeout through `context`, and results sent over a channel. Then add a data race on purpose, catch it with `-race`, and fix it. On Windows, `-race` needs a C toolchain, so run it in a `golang` Docker container if you don't have one.
**You can move on when:** Your program passes `-race`, stops cleanly on timeout, and you can explain what keeps running when one goroutine blocks.
