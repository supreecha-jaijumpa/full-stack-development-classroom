# 16.5 API Gateway & Backend-for-Frontend

> Module 16 — System Design & Architecture · Phase 5

**What you'll learn:** How gateway and BFF layers route, aggregate, and tailor backend services for different clients.

- The API gateway role: routing, auth, rate limiting, TLS termination
- Cross-cutting concerns centralized at the edge vs duplicated per service
- Backend-for-Frontend: one tailored API per client type (web, mobile)
- Response aggregation and shaping to reduce client round-trips
- Versioning and backward compatibility at the boundary
- Where Next.js route handlers / server actions can act as a BFF

**Hands-on:** Design a BFF for a product with a web app and a mobile app that have different data needs; document why a single shared API would be worse.
**You can move on when:** You can justify adding a BFF for a specific client and describe what the gateway handles versus the services behind it.
