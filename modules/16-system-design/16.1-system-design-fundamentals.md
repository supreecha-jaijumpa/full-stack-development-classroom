# 16.1 System Design Fundamentals

> Module 16 — System Design & Architecture · Phase 5

**What you'll learn:** A repeatable framework for approaching any system design problem from requirements to trade-offs.

- Clarifying functional vs non-functional requirements before designing anything
- Back-of-the-envelope estimation: traffic, storage, bandwidth, QPS
- The standard flow: requirements → API contract → data model → high-level architecture → scale → trade-offs
- Core building blocks: load balancers, app servers, databases, caches, CDNs, queues
- Latency vs throughput, and the CAP theorem in practical terms
- Communicating a design clearly with diagrams and stated assumptions

**Hands-on:** Write a one-page design framework cheat-sheet and apply it to a URL shortener.
**You can move on when:** You can take a vague brief and produce requirements, estimates, an API sketch, and a high-level diagram without prompting.
