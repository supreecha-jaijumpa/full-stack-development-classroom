# Module 17: Senior Engineering Practices

> Status: 🔒 Locked (complete the previous module first)
> Estimated Time: 3 weeks
> Phase: Phase 5 — Senior Level
> Fast Track: See the entry point table in `plan/roadmap.md`.

---

## Learning Objectives
- [ ] Conduct thorough, kind code reviews that catch correctness, design, and security issues
- [ ] Write clear design docs / RFCs that align a team before code is written
- [ ] Debug live production issues using logs, metrics, and traces under pressure
- [ ] Run an incident response and write a blameless postmortem with action items
- [ ] Estimate technical work and communicate uncertainty honestly
- [ ] Mentor others and communicate technical decisions to varied audiences
- [ ] Identify, quantify, and pay down technical debt deliberately

## Exercises
*(Unlocks as each topic is covered)*
- [ ] Exercise 17.1: Review a provided PR and leave written comments that flag at least one correctness, one design, and one security issue, each with a suggested fix.
- [ ] Exercise 17.2: Write a design doc / RFC for a feature in your capstone, including context, goals, alternatives considered, and a chosen approach.
- [ ] Exercise 17.3: Given a set of logs/metrics for a failing service, write up your diagnosis: hypothesis, evidence, root cause, and the fix.
- [ ] Exercise 17.4: Write a blameless postmortem for a hypothetical incident, including timeline, root cause, impact, and concrete action items.
- [ ] Exercise 17.5: Estimate a multi-part feature using a breakdown, give a range with confidence, and list the assumptions and risks behind it.
- [ ] Exercise 17.6: Write two explanations of the same technical decision — one for an engineer, one for a non-technical stakeholder.
- [ ] Exercise 17.7: Audit a codebase you've worked in, log the top tech-debt items with cost/impact, and propose a prioritized paydown plan.
