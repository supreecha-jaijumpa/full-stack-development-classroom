# 17.1 Code Review Practices

> Module 17 — Senior Engineering Practices · Phase 5

**What you'll learn:** How to review code in a way that catches real problems while keeping authors motivated.

- What to look for: correctness, design, readability, tests, security
- Separating blocking issues from nits and personal preference
- Writing comments that are specific, kind, and actionable
- Reviewing for what's missing (edge cases, error handling, tests), not just what's present
- Scope and size: why small PRs get better reviews
- Knowing when to approve, request changes, or pair instead

**Hands-on:** Review a provided PR and leave written comments flagging at least one correctness, one design, and one security issue, each with a suggested fix.
**You can move on when:** Your review on a real PR surfaces genuine issues and an author would feel helped rather than attacked.
