# 13.4 Next.js on a Go API

> Module 13 — Full-Stack Integration · Phase 4

**What you'll learn:** How to use Next.js as the frontend while the Go API owns business logic and the database.

- App Router structure, layouts, and file-based routing
- Server Components vs. Client Components when the data lives in another service
- Fetching from the Go API on the server and passing the result to the UI
- Route handlers as a thin layer for cookies and forwarding, not business logic
- Why only the Go API talks to the database
- Next.js server code runs on Node: when `await` frees the thread, and what still blocks it

**Hands-on:** Build a Next.js page that renders data fetched on the server from your Go API.
**You can move on when:** A Next.js page renders real DB data that came through the Go API, and you can explain where a blocking call would hurt.
