# 13.2 End-to-End Type Safety (OpenAPI)

> Module 13 — Full-Stack Integration · Phase 4

**What you'll learn:** How to keep one source of truth for an API when the client is TypeScript and the server is Go, so they can't silently disagree.

- Why TypeScript types can't be shared directly with Go, and what that costs
- OpenAPI as the contract between frontend and backend
- Generating Gin server interfaces and models with `oapi-codegen`
- Generating TypeScript types with `openapi-typescript`
- Validating runtime data at the boundary, not just trusting types
- Catching contract breaks at compile time and in CI

**Hands-on:** Write an OpenAPI contract for one endpoint and generate both the Go server code and the TypeScript types from it.
**You can move on when:** Changing the contract causes a compile error in both the frontend and the backend after regeneration.
