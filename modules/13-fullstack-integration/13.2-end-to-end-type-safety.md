# 13.2 End-to-End Type Safety

> Module 13 — Full-Stack Integration · Phase 4

**What you'll learn:** How to share one source of truth for types so the client and server can never silently disagree.

- Defining shared request/response types in a common package
- Generating or inferring types from Prisma and validation schemas (e.g. Zod)
- Inferring API types end-to-end (tRPC-style patterns or generated clients)
- Validating runtime data at the boundary, not just trusting types
- Catching contract breaks at compile time instead of in production

**Hands-on:** Create a shared types package and consume the same types on both sides of one endpoint.
**You can move on when:** Changing a shared type causes a compile error in both the frontend and backend.
