# 3.6 — Async, Promises & fetch

> Module: 03 — JavaScript Fundamentals · First taught: 2026-06-23 · Last updated: 2026-06-23

## TL;DR
JavaScript is single-threaded — only one thing runs at a time — so I/O operations (network, timers) are handled asynchronously: the browser runs the waiting in its own threads and calls back into JS when the result is ready. The language evolved from callbacks → Promises → async/await, each layer adding readability while keeping the same underlying mechanism. `fetch` is the built-in HTTP client; it follows Promise conventions and requires two awaits: one for the response headers, one for the response body.

## Key Concepts

### Single-threaded JS and the Event Loop
JavaScript has one execution thread. If a network request blocked that thread, the browser's entire UI would freeze until the response arrived — no scrolling, no clicks, nothing. Instead, JS delegates the waiting to the browser/runtime (which has its own I/O threads), and uses an event queue to call back into JS when the result is ready. This mechanism is the event loop.

```
JS thread:   [code runs] → [delegates fetch to browser] → [other code runs] → [callback fires when response arrives]
Browser I/O:                [actual HTTP wait happens here]
```

### Callbacks
The original async mechanism — "when you're done, run this function."

```js
setTimeout(function() {
  console.log("1 second later")
}, 1000)

console.log("this runs first") // prints immediately
```

**Problem — callback hell:** Sequential async steps that depend on each other's results nest deeply:

```js
getUser(userId, function(user) {
  getRepos(user.id, function(repos) {
    getDetails(repos[0].id, function(details) {
      // actual work — three levels deep, error handling at every level
    })
  })
})
```

### Promises
A Promise is an object representing a future value. Three states:
- **pending** — work is in progress
- **fulfilled** — done, has a resolved value
- **rejected** — failed, has a reason

```js
const p = new Promise((resolve, reject) => {
  setTimeout(() => resolve("done!"), 1000)
})

p
  .then(value => console.log(value))    // runs on fulfillment
  .catch(err => console.error(err))     // runs on rejection
  .finally(() => console.log("always")) // always runs
```

Chaining `.then()` calls flattens the nested-callback structure:

```js
getUser(id)
  .then(user => getRepos(user.id))        // return the next Promise
  .then(repos => getDetails(repos[0].id))
  .then(details => { /* work here */ })
  .catch(err => console.error(err))       // ONE handler for the whole chain
```

### async/await
Syntax sugar over Promises. Same engine underneath — just synchronous-looking code.

```js
async function loadData(id) {    // always returns a Promise
  try {
    const user = await getUser(id)       // pauses here; other code still runs
    const repos = await getRepos(user.id)
    return repos
  } catch (err) {
    console.error(err)
  }
}
```

Key rules:
- `async` before a function makes it **always return a Promise** — even `async function f() { return 42 }` returns `Promise { 42 }`, not `42`
- `await` can only appear inside an `async` function
- `await` unwraps the resolved value, or throws if the Promise is rejected

### fetch — the built-in HTTP client
`fetch` returns a Promise. The response arrives in two stages: headers first, then the body — so two awaits are required:

```js
async function getUser(username) {
  const response = await fetch(`https://api.github.com/users/${username}`)

  // fetch does NOT throw on 404/500 — only on network failure
  if (!response.ok) {
    throw new Error(`HTTP error: ${response.status}`)
  }

  const data = await response.json()   // parses the body — also a Promise
  return data
}
```

### Promise.all — parallel requests
When two requests are independent (neither needs the other's result), fire them simultaneously:

```js
// Sequential — 2× the wait time
const userRes = await fetch(USER_URL)
const reposRes = await fetch(REPOS_URL)

// Parallel — resolves when BOTH settle; wall-clock = slowest single request
const [userRes, reposRes] = await Promise.all([
  fetch(USER_URL),
  fetch(REPOS_URL),
])
```

`Promise.all` rejects immediately if any Promise rejects (fail-fast behavior).

## Examples

### GitHub user summary (full exercise)
```js
async function main() {
  const BASE = "https://api.github.com/users/torvalds"

  const [userRes, reposRes] = await Promise.all([
    fetch(BASE),
    fetch(`${BASE}/repos`),
  ])

  if (!userRes.ok) throw new Error(`User fetch failed: ${userRes.status}`)
  if (!reposRes.ok) throw new Error(`Repos fetch failed: ${reposRes.status}`)

  const user = await userRes.json()
  const repos = await reposRes.json()

  const top3 = [...repos]
    .sort((a, b) => b.stargazers_count - a.stargazers_count)
    .slice(0, 3)

  console.log(`Name: ${user.name}`)
  console.log(`Public repos: ${user.public_repos}`)
  console.log("Top 3 repos by stars:")
  for (const repo of top3) {
    console.log(`  ${repo.name} — ${repo.stargazers_count} stars`)
  }
}

main().catch(err => console.error(`Error: ${err.message}`))
```

Output:
```
Name: Linus Torvalds
Public repos: 12
Top 3 repos by stars:
  linux — 237309 stars
  AudioNoise — 4384 stars
  uemacs — 2055 stars
```

Note: `main().catch()` at the top level is the standard Node.js pattern for handling uncaught async errors in a script.

## Common Pitfalls

- **`fetch` doesn't throw on 4xx/5xx**: It only rejects on network failure (offline, DNS error). A 404 or 500 still resolves — with `response.ok === false`. Always check `response.ok` before calling `.json()`.
- **Missing the second `await`**: `await fetch(url)` gives you the Response object, not the parsed data. You must also `await response.json()` to get the body.
- **Sequential awaits for independent requests**: Two `await fetch()` in a row take 2× the wall-clock time. Use `Promise.all` whenever requests don't depend on each other.
- **`async` without `await` (or vice versa)**: `await` outside an `async` function is a syntax error. An `async` function that never `await`s anything is valid but usually a mistake.
- **Not handling `Promise.all` rejections**: If any Promise in the array rejects, `Promise.all` rejects immediately. Wrap in `try/catch` or chain `.catch()`.
