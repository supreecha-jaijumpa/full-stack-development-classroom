# 3.2 — Functions & Scope

> Module: 03 — JavaScript Fundamentals · First taught: 2026-06-23 · Last updated: 2026-06-23

## TL;DR
JavaScript has three scope levels: global, function, and block. `let`/`const` are block-scoped; `var` is function-scoped and leaks out of blocks. A closure is an inner function that retains a **live reference** to the scope it was born in — not a copy of the value. Arrow functions don't have their own `this`; they inherit it from the enclosing scope at definition time. Regular function `this` depends on the call site, not where the function is defined.

## Key Concepts

### Scope

Every identifier in JavaScript lives in a scope — a boundary that determines where it can be seen.

```js
let global = "everywhere";    // global scope

function outer() {
  let fn = "inside outer";    // function scope

  if (true) {
    let block = "block only"; // block scope (let/const)
    var leaked = "oops";      // var ignores block — hoists to function scope
  }

  console.log(fn);     // ✅
  console.log(block);  // ❌ ReferenceError
  console.log(leaked); // ✅ var leaked out of the if-block
}
```

**Rule:** a function can see its own scope and everything above it in the chain, never below.

The three levels:

| Scope | Created by | `let`/`const` | `var` |
|-------|-----------|----------------|-------|
| Global | Top level | ✅ visible everywhere | ✅ visible everywhere |
| Function | A function call | ✅ scoped to function | ✅ scoped to function |
| Block | `{}` (if, for, while…) | ✅ scoped to block | ❌ leaks to function |

### Closures

A closure is a function that retains a **live reference** to the scope it was created in — even after the outer function has returned.

```js
function makeCounter() {
  let count = 0;          // this scope stays alive...
  return () => {
    count++;              // ...because this function holds a reference to it
    return count;
  };
}

const a = makeCounter();
const b = makeCounter();

a(); // 1
a(); // 2
b(); // 1  ← independent — its own scope, its own count
```

Each call to `makeCounter()` creates a **new scope** with its own `count`. The returned function is bundled with that scope — that bundle is the closure. Two calls = two scopes = two independent counters.

Key insight: a closure captures the **binding** (the variable slot in memory), not a snapshot of the value at call time. Any mutation to the variable is visible through the closure.

### Factory Functions

A factory function is any function that returns a new object or function. Each call produces an independent instance with its own private state via closure:

```js
function makeAdder(x) {
  return (y) => x + y;
}

const add5  = makeAdder(5);
const add10 = makeAdder(10);

add5(3);  // 8
add10(3); // 13
```

### `this` — call-site vs lexical scope

**Regular functions:** `this` is set by the **call site** — whoever calls the function.

```js
const user = {
  name: "Alice",
  greet: function () {
    console.log(this.name);
  },
};

user.greet();           // "Alice" — called on the object, this = user
const fn = user.greet;
fn();                   // undefined — called bare, this = global / undefined (strict)
```

**Arrow functions:** no own `this`. They inherit `this` from the **enclosing scope at definition time** (lexical `this`).

```js
const user = {
  name: "Alice",
  greet: function () {
    const inner = () => console.log(this.name); // inherits this from greet
    inner();
  },
};

user.greet(); // "Alice" ✅
```

## Examples

### React `useState` is a closure

Every `useState` call closes over a per-component state slot. Each component instance gets its own `count` because each function call creates its own scope — the same mechanism as `makeCounter()`.

```jsx
function Counter() {
  const [count, setCount] = useState(0);
  // onClick closes over count and setCount — that's a closure
  return <button onClick={() => setCount(count + 1)}>{count}</button>;
}
```

### Factory with multiple methods

```js
function makeCounter(start = 0) {
  let count = start;
  return {
    increment: () => ++count,
    decrement: () => --count,
    value:     () => count,
  };
}

const a = makeCounter();
const b = makeCounter(10);

a.increment(); a.increment();
b.decrement();

a.value(); // 2
b.value(); // 9
```

## Common Pitfalls

**`var` leaking out of blocks:** A common mistake is declaring a loop variable with `var` and being surprised it exists outside the loop:
```js
for (var i = 0; i < 3; i++) {}
console.log(i); // 3 — leaked! Use let instead.
```

**Assuming closures snapshot the value:** Closures capture the live binding, not the value at creation time:
```js
let x = 1;
const getX = () => x;
x = 99;
getX(); // 99 — sees the current value, not 1
```

**Using reserved words as parameter names:** `default`, `class`, `return`, and other reserved keywords cannot be used as variable or parameter names — the parser throws a SyntaxError before the code runs.

**Losing `this` by detaching a method:** Assigning a method to a variable strips the object context. Arrow functions avoid this because they have no own `this` to lose.
