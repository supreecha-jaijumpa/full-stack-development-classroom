# 3.5 — Events

> Module 03 — JavaScript Fundamentals · Phase 1 · Completed 2026-06-23

## Core Concept

Events are how the browser tells your code that something happened. Every user interaction (click, keypress, form submit) fires an event object that bubbles up the DOM tree.

---

## addEventListener

```js
element.addEventListener('click', handler)
element.removeEventListener('click', handler)  // must be same function reference
```

React's `onClick` / `onChange` / `onSubmit` props compile down to `addEventListener` calls.

---

## The Event Object

Every handler receives one argument — the Event object.

| Property | Value |
|---|---|
| `e.type` | `"click"`, `"input"`, `"submit"`, etc. |
| `e.target` | The element that was **actually clicked** (origin — never changes as it bubbles) |
| `e.currentTarget` | The element **the listener is attached to** (changes at each bubble level) |
| `e.key` | `"Enter"`, `"a"`, `"Backspace"` — for keyboard events |

```js
card.addEventListener('click', (e) => {
  e.target        // the inner element you clicked (e.g. a <button> inside the card)
  e.currentTarget // the <div#card> where the listener lives
})
```

---

## Event Bubbling

A click on `<button>` inside `<div>` fires at the button first, then bubbles up to `<div>`, `<body>`, `<html>`, `document`.

```
click on <li>
  ▼  e.target = <li>  (frozen)
 <li>   e.currentTarget = <li>
  ▼ bubble
 <ul>   e.currentTarget = <ul>
  ▼ bubble
document  e.currentTarget = document
```

`stopPropagation()` kills the bubble at that level — parent listeners never fire.

```js
button.addEventListener('click', (e) => {
  e.stopPropagation()  // card's onClick won't fire
})
```

---

## preventDefault

Stops the browser's default behavior for the event.

| Element | Default | Use case |
|---|---|---|
| `<form>` submit | Page reload | Handle with JS |
| `<a>` click | Navigate | SPA routing |
| `<input type="checkbox">` click | Toggle | Custom logic |

```js
form.addEventListener('submit', (e) => {
  e.preventDefault()
  const email = e.target.elements['email'].value
})
```

---

## Event Delegation

Add **one listener on the parent** — use `e.target` + `closest()` to identify which child was interacted with.

```js
list.addEventListener('click', (e) => {
  const item = e.target.closest('li')  // handles nested children safely
  if (!item) return
  console.log(item.dataset.id)
})
```

**Why `closest()` over `e.target` directly:** if an `<li>` has a `<span>` inside it, `e.target` is the `<span>`. `closest('li')` walks up to find the right ancestor.

### React uses this pattern

React attaches **one listener per event type** to `<div id="root">`, not one per component. Because of bubbling, every click reaches the root. React reads `e.target` to match it to the correct component's handler. Result: 10,000 `onClick` props = 1 DOM listener.

---

## Common Event Types

| Event | Fires when |
|---|---|
| `click` | Mouse click |
| `input` | Input value changes (every keystroke) |
| `change` | Input loses focus after value change |
| `submit` | Form submitted |
| `keydown` | Key pressed (use `e.key`) |
| `mouseenter` / `mouseleave` | Hover (don't bubble) |
| `focus` / `blur` | Focus enters/leaves element |

## Exercise Built

Delegated list + form submit:
```html
<ul id="item-list">
  <li data-id="item-1">Item One</li>
  <li data-id="item-2">Item Two</li>
  <li data-id="item-3">Item Three</li>
</ul>
<form id="email-form">
  <input type="email" id="email-input" required>
  <button type="submit">Submit</button>
</form>
<p id="email-display"></p>

<script>
  document.getElementById('item-list').addEventListener('click', (e) => {
    const li = e.target.closest('li')
    if (li) console.log('Clicked item id:', li.dataset.id)
  })

  document.getElementById('email-form').addEventListener('submit', (e) => {
    e.preventDefault()
    const email = document.getElementById('email-input').value
    document.getElementById('email-display').textContent = email  // textContent not innerHTML — XSS safety
  })
</script>
```

**Notable choices:** `closest('li')` handles nested children; `textContent` over `innerHTML` prevents XSS on user input.
