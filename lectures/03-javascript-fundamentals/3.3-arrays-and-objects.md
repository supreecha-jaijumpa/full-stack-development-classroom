# 3.3 — Arrays & Objects

> Module: 03 — JavaScript Fundamentals · First taught: 2026-06-23 · Last updated: 2026-06-23

## TL;DR

JavaScript arrays and objects are the primary containers for data. Array methods split into two kinds — mutating (change the original) and non-mutating (return something new) — and knowing which is which prevents a whole class of bugs, especially in React. Higher-order methods (`map`, `filter`, `reduce`) let you transform data declaratively without loops. Objects can be iterated with `Object.entries` and safely merged with spread.

## Key Concepts

### Mutating vs Non-Mutating Methods

A **mutating** method changes the original array in place. A **non-mutating** method returns a new array or value and leaves the original untouched.

```js
const nums = [3, 1, 2];

// MUTATING — original is changed
nums.sort();       // nums is now [1, 2, 3]
nums.push(4);      // nums is now [1, 2, 3, 4]
nums.splice(0, 1); // nums is now [2, 3, 4]

// NON-MUTATING — original stays [2, 3, 4]
const doubled = nums.map(n => n * 2);          // [4, 6, 8]
const evens   = nums.filter(n => n % 2 === 0); // [2, 4]
const sum     = nums.reduce((acc, n) => acc + n, 0); // 9
```

Mutating: `push`, `pop`, `shift`, `unshift`, `splice`, `sort`, `reverse`, `fill`
Non-mutating: `map`, `filter`, `reduce`, `find`, `findIndex`, `some`, `every`, `slice`, `concat`, `flat`

### Why React Cares

React's re-render check compares **object references**, not contents. If you mutate the same array and pass back the same reference, React thinks nothing changed and skips the re-render.

```js
// BAD — same reference, no re-render
items.push(newItem);
setItems(items);

// GOOD — new reference, triggers re-render
setItems([...items, newItem]);
```

This is the fundamental reason React code uses `map`, `filter`, and spread instead of `push`, `splice`, or `sort`.

### Higher-Order Methods

**`filter`** — keeps only elements that pass a test; returns a new array:
```js
const adults = users.filter(u => u.age >= 18);
const active = users.filter(u => u.active && u.age >= 18); // combine conditions
```

**`map`** — transforms every element; returns a new array of the same length:
```js
const names  = users.map(u => u.name);
const labels = users.map(u => `${u.name} (${u.age})`);
```

**`reduce`** — accumulates to a single output (number, string, object, or array):
```js
// Sum
const total = [1, 2, 3].reduce((acc, n) => acc + n, 0); // 6

// Frequency map
const byLang = repos.reduce((acc, repo) => {
  acc[repo.language] = (acc[repo.language] || 0) + 1;
  return acc;
}, {});
// { JavaScript: 2, TypeScript: 2 }

// Array-to-lookup by id
const byId = users.reduce((acc, user) => {
  acc[user.id] = user;
  return acc;
}, {});
// { 1: { id: 1, name: 'Alice' }, 2: { id: 2, name: 'Bob' } }
```

`reduce` is the right tool when `map` or `filter` alone can't produce the shape you need.

### sort() Is Mutating — Always Spread First

```js
// BAD — sorts the state array directly
const sorted = users.sort((a, b) => a.age - b.age);

// GOOD — spread creates a new array first
const sorted = [...users].sort((a, b) => a.age - b.age);
```

After a `.filter()` or `.map()`, the result is already a new array, so chaining `.sort()` onto it is safe. The habit matters when sorting an array you received directly (e.g., from state or a prop).

### Array Spread

Spread expands an array's items inline:
```js
const a = [1, 2, 3];
const b = [4, 5];

const c = [...a, ...b];    // [1, 2, 3, 4, 5]
const d = [...a, 0, ...b]; // [1, 2, 3, 0, 4, 5]
```

### Object Spread

Spread merges objects. When the same key appears in multiple sources, **the last one wins**:

```js
const user    = { name: 'Alice', role: 'admin' };
const updated = { ...user, role: 'viewer', age: 30 };
// { name: 'Alice', role: 'viewer', age: 30 }
```

Standard React state update pattern:
```js
setUser(prev => ({ ...prev, role: 'viewer' }));
```

### Destructuring

Destructuring extracts values by name (objects) or by position (arrays):

```js
// Object destructuring
const { name, age } = user;

// With rename
const { name: userName } = user;

// Array destructuring (React useState)
const [count, setCount] = useState(0);

// Function parameter destructuring
function greet({ name, age }) {
  return `${name} is ${age}`;
}
```

### Object.entries and Object.keys

`Object.entries(obj)` returns an array of `[key, value]` tuples — own enumerable properties only:

```js
const scores = { alice: 95, bob: 72, carol: 88 };

Object.entries(scores).forEach(([name, score]) => {
  console.log(`${name}: ${score}`);
});
// alice: 95
// bob: 72
// carol: 88
```

`Object.keys(obj)` — just the keys. `Object.values(obj)` — just the values.

Prefer `Object.entries` over `for...in` — `for...in` also iterates inherited prototype properties, which is almost never what you want.

## Examples

### Chaining filter + map (GitHub repos)

```js
const repos = [
  { name: 'react',    stars: 220000, language: 'JavaScript', archived: false },
  { name: 'next.js',  stars: 125000, language: 'TypeScript',  archived: false },
  { name: 'old-tool', stars: 800,    language: 'JavaScript', archived: true  },
  { name: 'vite',     stars: 68000,  language: 'TypeScript',  archived: false },
];

const result = repos
  .filter(r => !r.archived && r.language.toLowerCase() === 'typescript')
  .map(r => `${r.name} — ${r.stars} stars`);

// ["next.js — 125000 stars", "vite — 68000 stars"]
```

### reduce to frequency map

```js
const byLang = repos.reduce((acc, repo) => {
  acc[repo.language] = (acc[repo.language] || 0) + 1;
  return acc;
}, {});

// { JavaScript: 2, TypeScript: 2 }
// (archived repos still count — no filter applied)
```

### Filter + sort + map chain

```js
const users = [
  { name: 'Alice', age: 28, active: true  },
  { name: 'Bob',   age: 17, active: true  },
  { name: 'Dave',  age: 22, active: true  },
  { name: 'Eve',   age: 19, active: true  },
];

const result = users
  .filter(u => u.active && u.age >= 18)
  .sort((a, b) => a.age - b.age)   // safe: filter already returned a new array
  .map(u => `${u.name} (${u.age})`);

// ["Eve (19)", "Dave (22)", "Alice (28)"]
```

## Common Pitfalls

**Confusing which methods mutate:** A common mistake is assuming `map` and `filter` mutate the array while `forEach` doesn't. It's the opposite — `map` and `filter` return new arrays; `push`, `sort`, and `splice` mutate in place.

**Zero is falsy:** When counting into an object, `if (acc[key])` fails when the count reaches `0` — `0` is falsy, so the branch doesn't fire. Use `(acc[key] || 0) + 1` to guard against this.

**sort() on state:** `arr.sort()` mutates in place and returns the same reference — React skips the re-render. Always spread first: `[...arr].sort(...)`.

**Object.entries shape:** `Object.entries` returns `[[key, value], ...]` — an array of two-element arrays, not `[{ key, value }, ...]`. Destructure as `([k, v])`, not `({ key, value })`.

**for...in on objects:** `for...in` iterates all enumerable properties including inherited ones from the prototype chain. Use `Object.entries` or `Object.keys` for plain object iteration.

**Missing `()` on method calls:** `arr.toLowerCase` is the function object (truthy), not the result. Always call it: `arr.toLowerCase()`.
