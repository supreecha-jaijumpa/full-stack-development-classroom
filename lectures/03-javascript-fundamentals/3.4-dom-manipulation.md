# 3.4 — DOM Manipulation

> Module: 03 — JavaScript Fundamentals · First taught: 2026-06-23 · Last updated: 2026-06-23

## TL;DR
The DOM is a tree of node objects the browser builds from HTML. JavaScript can read and mutate this tree to change the page — selecting elements, updating content and attributes, creating new nodes, and removing old ones. Minimizing DOM writes is critical for performance; batching them with `DocumentFragment` is the manual solution, and it is the core problem React's virtual DOM and reconciliation algorithm solve structurally.

## Key Concepts

### The DOM as a Tree
When the browser parses HTML it builds a tree of node objects in memory called the Document Object Model. Every element is a node with a parent, children, and siblings. `document` is the root entry point from JavaScript.

```
body
└── div#app
    ├── h1 ("Hello")
    └── ul
        ├── li ("Item 1")
        └── li ("Item 2")
```

### Selecting Elements
`document.querySelector(selector)` returns the **first** matching element, or `null` if none found.  
`document.querySelectorAll(selector)` returns a **NodeList** of all matches.

NodeList is not an array — it lacks `.map`, `.filter`, etc. Spread it to get a real array:

```js
const items = document.querySelectorAll('li');
[...items].map(item => item.textContent);  // works
items.map(...);                            // TypeError
```

### Reading and Changing Content

```js
const h1 = document.querySelector('h1');

h1.textContent = 'Hello, World!';       // safe — no HTML parsed
h1.innerHTML   = '<em>Hello</em>';      // parses HTML — XSS risk with user input

const link = document.querySelector('a');
link.getAttribute('href');
link.setAttribute('href', 'https://github.com');
```

### Manipulating Classes

```js
const el = document.querySelector('.card');
el.classList.add('active');
el.classList.remove('active');
el.classList.toggle('active');      // adds if absent, removes if present
el.classList.contains('active');    // returns true/false
```

### Creating and Removing Elements

```js
const li = document.createElement('li');   // in-memory, not yet in the document
li.textContent = 'New Item';

const ul = document.querySelector('ul');
ul.appendChild(li);   // add at the end
ul.prepend(li);       // add at the start

li.remove();          // removes itself from the DOM
```

### DocumentFragment for Batch Writes
`document.createDocumentFragment()` creates an in-memory container that lives outside the main document tree. Appending children to it triggers **no reflow**. One final `parent.appendChild(fragment)` flushes everything to the live DOM in a single write.

```js
// BAD — touches DOM 1000 times
for (let i = 0; i < 1000; i++) {
  ul.innerHTML += `<li>Item ${i}</li>`;  // reads + writes every iteration
}

// GOOD — touches DOM once
const fragment = document.createDocumentFragment();
for (let i = 0; i < 1000; i++) {
  const li = document.createElement('li');
  li.textContent = `Item ${i}`;
  fragment.appendChild(li);    // in-memory, zero DOM cost
}
ul.appendChild(fragment);      // one write
```

### The Cost of DOM Updates — Why React Exists
Every DOM write may trigger a **reflow** (browser recalculates layout geometry) and a **repaint**. The cost scales with how many nodes are affected and how deeply they're nested.

React's virtual DOM is a lightweight in-memory copy of the real DOM. On every state change React:
1. Diffs the new virtual tree against the previous one
2. Computes the minimum set of real DOM changes needed
3. Applies only those changes in a single batched write

The `key` prop in React lists plays the same role as a `data-id` attribute: it gives the differ a stable identity to match old nodes against new ones, so unchanged items aren't destroyed and recreated unnecessarily.

### Array as Source of Truth (the Re-Render Pattern)
The clean pattern for managing a DOM list in vanilla JS mirrors React exactly:

1. Keep an array as the canonical state (`tasks = []`)
2. Mutate the array first (push, splice)
3. Call a `render()` function that rebuilds the DOM entirely from the array

React formalizes this with `useState` + JSX + a render cycle. The mental model is identical.

## Examples

### To-Do List — array as source of truth

```js
const tasks = [];

function render() {
  list.innerHTML = '';
  const fragment = document.createDocumentFragment();

  tasks.forEach((task, index) => {
    const li   = document.createElement('li');
    const span = document.createElement('span');
    span.textContent = task;

    const btn = document.createElement('button');
    btn.textContent = '×';
    btn.addEventListener('click', () => {
      tasks.splice(index, 1);  // mutate array first
      render();                // re-render from updated array
    });

    li.appendChild(span);
    li.appendChild(btn);
    fragment.appendChild(li);
  });

  list.appendChild(fragment);  // one DOM write
}

function addTask() {
  const text = input.value.trim();
  if (!text) return;
  tasks.push(text);
  input.value = '';
  render();
}
```

### ID-Based Diffing — the React `key` insight

Instead of wiping and rebuilding on every render, assign a stable ID to each item and only touch changed nodes:

```js
let nextId = 0;
tasks.push({ id: ++nextId, text });

function render() {
  // Add DOM nodes for IDs not yet in the list
  tasks.forEach(task => {
    if (!list.querySelector(`[data-id="${task.id}"]`)) {
      const li = document.createElement('li');
      li.dataset.id = task.id;
      li.textContent = task.text;
      list.appendChild(li);
    }
  });

  // Remove DOM nodes whose ID is no longer in tasks
  [...list.children].forEach(li => {
    if (!tasks.find(t => t.id === Number(li.dataset.id))) {
      li.remove();
    }
  });
}
```

This is the virtual DOM diff algorithm in miniature. Using array index as `key` in React breaks this because when items reorder, index and identity no longer match — React thinks an existing item was replaced rather than moved.

## Common Pitfalls
- Using `innerHTML +=` inside a loop reads and destroys all existing children on every iteration — creating N full DOM rewrites instead of 1.
- `querySelectorAll` returns a `NodeList`, not an array — calling `.map` on it throws a TypeError.
- `innerHTML` with unsanitized user input is an XSS vector — use `textContent` for plain text.
- Using array index as React `key` when items can be reordered or inserted causes unnecessary re-creation and can break animations and focus state.
- Full `innerHTML = ''` + rebuild on every change is correct and simple for small lists; at scale it destroys event listeners and is expensive — the key-based diffing pattern avoids it.
