# 3.1 — Variables, Types & Operators

> Module: 03 — JavaScript Fundamentals · First taught: 2026-06-22 · Last updated: 2026-06-22

## TL;DR
JavaScript has two reliable variable declarations — `const` for bindings that won't be reassigned and `let` for mutable values. Primitive types coerce freely in implicit operations, and the `==` operator runs a multi-step coercion algorithm that produces non-obvious results. Use `===` everywhere except the intentional `x == null` null-check pattern. `null` and `undefined` coerce differently, and `null` behaves inconsistently across `==` vs comparison operators — a known spec quirk.

## Key Concepts

### `let` vs `const` vs `var`

- `const` — block-scoped, must be initialized, the binding can't be reassigned (objects/arrays can still mutate)
- `let` — block-scoped, mutable, can be declared without initialization
- `var` — function-scoped, hoisted to the top of its function, no block scope — avoid in modern JS

```js
const name = "Spotify"
let count = 0
count = 1      // ok
name = "Apple" // TypeError: Assignment to constant variable
```

### Primitive Types

JavaScript has 7 primitive types:

| Type | Example | Notes |
|------|---------|-------|
| string | `"hello"` | Immutable UTF-16 sequence |
| number | `42`, `3.14`, `NaN`, `Infinity` | All numbers are 64-bit floats |
| boolean | `true`, `false` | |
| null | `null` | Intentional absence of a value |
| undefined | `undefined` | Variable declared but not assigned |
| symbol | `Symbol("id")` | Unique identity token |
| bigint | `9007199254740991n` | Integers beyond `Number.MAX_SAFE_INTEGER` |

`NaN` is type `number` — it means "this operation couldn't produce a valid number."

### `===` vs `==` — Strict vs Abstract Equality

`===` checks value **and** type with no coercion:

```js
0 === "0"    // false — number vs string, stops here
```

`==` runs an abstract equality algorithm that converts types step by step:

```js
0 == "0"     // true — "0" coerces to 0
```

**The coercion chain that surprises everyone — `[] == false`:**

```
[] == false
→ [] == 0         (false → 0)
→ "" == 0         ([] → "" via .toString())
→ 0  == 0         ("" → 0)
→ true
```

**Rule:** Use `===` everywhere. The one valid exception is the intentional null-check:

```js
if (x == null) { ... }  // catches both null AND undefined — accepted pattern
```

### How Types Coerce to Numbers

| Value | As number | Example |
|-------|-----------|---------|
| `null` | `0` | `null + 1` → `1` |
| `undefined` | `NaN` | `undefined + 1` → `NaN` |
| `""` | `0` | `"" - 0` → `0` |
| `"5"` | `5` | `"5" - 3` → `2` |
| `[]` | `0` | (via `""` → `0`) |
| `true` | `1` | |
| `false` | `0` | |

### `null` Comparison Inconsistency (Famous JS Gotcha)

```js
null > 0    // false  — numeric: 0 > 0 is false
null == 0   // false  — special rule: null only == null or undefined
null >= 0   // true   — numeric: 0 >= 0 is true ← inconsistent with the above
```

`==` has a hard-coded spec exception: `null` only ever equals `null` or `undefined`, regardless of what `null` coerces to numerically. But comparison operators (`>`, `>=`, `<`) always use the numeric path, giving `0 >= 0 → true`. This inconsistency is in the spec and will never change.

### `+` vs `-` Asymmetry with Strings

`+` is overloaded — if either operand is a string, it concatenates:

```js
"5" + 3   // "53" — string wins, concatenation
3 + "5"   // "35" — same rule, left-to-right doesn't matter for type
```

`-`, `*`, `/` are math-only — they always coerce to numbers first:

```js
"5" - 3   // 2  — "5" coerces to 5
"5" * 2   // 10
"abc" - 1 // NaN — "abc" can't become a number
```

### Truthy and Falsy Values

These six values are **falsy** — everything else is truthy:

```
false    0    -0    ""    null    undefined    NaN
```

**The `"0"` trap:** `"0"` is a non-empty string, so it's truthy — but `"0" == false` is `true` via coercion:

```js
Boolean("0")   // true  — non-empty string = truthy
"0" == false   // true  — coercion path: false→0, "0"→0, 0==0
```

These two facts are not contradictory — they just use different evaluation paths.

### `||` vs `??` — Default Value Patterns

`||` uses the right operand when the left side is **falsy** (includes `0`, `""`, `false`):

```js
const display = name || "Anonymous"
// If name is "" or 0, "Anonymous" wins — often not what you want
```

`??` (nullish coalescing) uses the right operand only when the left is `null` or `undefined`:

```js
const total = count ?? 10
// If count is 0, 0 wins — only null/undefined triggers the fallback
```

```js
0 || "default"   // "default" — 0 is falsy
0 ?? "default"   // 0 — 0 is not null/undefined
```

Use `??` when `0` or `""` are valid values you want to keep.

### Template Literals

Backtick strings — embed expressions with `${}` and span multiple lines:

```js
const user = "Supreecha"
const msg = `Hello, ${user}! You have ${count + 1} messages.`
```

## Common Pitfalls

- A common mistake is expecting `"5" - 3` to return `NaN`. Only `+` prefers string concatenation; `-`, `*`, `/` always coerce to numbers first.
- A common mistake is assuming `null == 0` is `true` because `null` coerces to `0`. The `==` operator has a hard-coded exception: `null` only equals `null` or `undefined`.
- A common mistake is using `||` to set default values for numbers or empty strings. `||` treats `0` and `""` as absent. Prefer `??` when you're specifically guarding against `null`/`undefined`.
- A common mistake is reasoning about `[]` as falsy. `Boolean([])` is `true` — empty arrays and objects are truthy. But `[] == false` is also `true` via the coercion chain. These are not contradictory; they use different evaluation paths.

## Quick Recall

1. What is the output of `null + 1`? Why?
2. What is the output of `null == 0`? Why does this differ from `null >= 0`?
3. What are the falsy values in JavaScript?
4. What is the difference between `||` and `??`?
5. Why does `"5" - 3` return `2` but `"5" + 3` returns `"53"`?

<details>
<summary>Answers</summary>

1. `1` — `null` coerces to `0` in numeric context, so `0 + 1 = 1`
2. `null == 0` is `false` — the `==` operator has a spec carve-out where `null` only equals `null` or `undefined`. `null >= 0` is `true` because comparison operators use the numeric path: `null → 0`, then `0 >= 0 → true`.
3. `false`, `0`, `-0`, `""`, `null`, `undefined`, `NaN`
4. `||` uses the right operand when the left is **falsy** (includes `0`, `""`). `??` uses the right operand only when the left is `null` or `undefined`.
5. `-` is math-only and coerces both sides to numbers. `+` is overloaded — if either side is a string, it concatenates.
