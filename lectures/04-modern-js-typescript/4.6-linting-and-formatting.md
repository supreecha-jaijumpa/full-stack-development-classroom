# 4.6 — Linting & Formatting (ESLint + Prettier)

> Module 04 · Completed 2026-06-26

## Core Distinction

| Tool | Owns | Example rules |
|------|------|---------------|
| ESLint | Correctness | `no-unused-vars`, type safety, bad patterns |
| Prettier | Style | spacing, quotes, semicolons, line length |
| `eslint-config-prettier` | Nothing | disables ESLint's style rules so there's no conflict |

**Rule of thumb:** if a rule is purely cosmetic (looks the same at runtime) → Prettier. If it can hide a bug → ESLint.

## Why Two TypeScript Packages

ESLint was built for JavaScript. TypeScript files need two replacements:

- **`@typescript-eslint/parser`** — replaces the JS parser so ESLint can read `.ts` syntax (generics, `as`, `interface`, etc.)
- **`@typescript-eslint/eslint-plugin`** — replaces JS rules with TS-aware versions. Example: built-in `no-unused-vars` flags `import type { User }` as unused; the plugin version understands type-only imports and stays quiet.

## Config (Flat Config — ESLint 9+)

**CJS project (`"type": "commonjs"`):**
```js
// eslint.config.js
const tsParser = require('@typescript-eslint/parser')
const tsPlugin = require('@typescript-eslint/eslint-plugin')
const prettierConfig = require('eslint-config-prettier')

module.exports = [
  {
    files: ['**/*.ts', '**/*.tsx'],
    languageOptions: { parser: tsParser },
    plugins: { '@typescript-eslint': tsPlugin },
    rules: { ...tsPlugin.configs.recommended.rules },
  },
  prettierConfig,  // must be LAST
]
```

**ESM project (`"type": "module"`):**
```js
// eslint.config.js
import tsParser from '@typescript-eslint/parser'
import tsPlugin from '@typescript-eslint/eslint-plugin'
import prettier from 'eslint-config-prettier'

export default [
  {
    files: ['**/*.ts', '**/*.tsx'],
    languageOptions: { parser: tsParser },
    plugins: { '@typescript-eslint': tsPlugin },
    rules: { ...tsPlugin.configs.recommended.rules },
  },
  prettier,  // must be LAST
]
```

`eslint-config-prettier` must be last — it overrides/disables conflicting rules from everything above it.

## npm Scripts

```json
{
  "scripts": {
    "lint": "eslint . --ext .ts,.tsx",
    "format": "prettier --write .",
    "format:check": "prettier --check ."
  }
}
```

`--write` rewrites files. `--check` exits non-zero if any file would change — use this in CI.

## CI & Pre-commit Gates

Two layers — both are needed:

```
git commit → [pre-commit hook] → git push → [CI check] → PR merge
```

**Pre-commit (Husky + lint-staged):**
```bash
npm install -D husky lint-staged
npx husky init
# edit .husky/pre-commit → npx lint-staged
```
```json
// package.json
{
  "lint-staged": {
    "*.{ts,tsx}": ["eslint --fix", "prettier --write"],
    "*.{json,css,md}": ["prettier --write"]
  }
}
```
lint-staged runs only on staged files — keeps commits fast.

**CI (GitHub Actions):**
```yaml
- run: npm ci
- run: npm run lint
- run: npm run format:check   # fails if files aren't formatted
```

Pre-commit hooks can be skipped with `--no-verify`. CI is the hard stop.
