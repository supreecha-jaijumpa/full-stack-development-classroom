## Key Techniques

### CSS Custom Property Design System

Three-level architecture applied across the whole page:

```css
/* Level 1 — global tokens */
:root {
  --green: #1DB954;
  --step-0: clamp(1rem, 0.95rem + 0.25vw, 1.1rem);
  --space-md: 1.5rem;
}

/* Level 2 — component API (with fallback to token) */
.player-card {
  background: rgba(255,255,255,0.05);
  border-radius: var(--radius-lg);
}

/* Level 3 — context override from a parent */
.cta-wave-bar {
  height: var(--h);          /* set inline on each bar */
  animation-delay: var(--delay); /* set inline on each bar */
}
```

### Fluid Type Scale with clamp()

```css
--step--1: clamp(0.8rem,  0.75rem + 0.25vw, 0.9rem);
--step-0:  clamp(1rem,    0.95rem + 0.25vw, 1.1rem);
--step-3:  clamp(2rem,    1.5rem  + 2.5vw,  3.5rem);
--step-4:  clamp(2.5rem,  1.8rem  + 3.5vw,  4.5rem);
```

Five named steps cover the full heading hierarchy. Every font-size in the page references a step variable, not a raw value.

### Mobile-First Layout Pattern

```css
/* base: mobile — one column */
.features__grid {
  display: grid;
  grid-template-columns: 1fr;
}

/* 640px: two columns */
@media (min-width: 640px) {
  .features__grid { grid-template-columns: repeat(2, 1fr); }
}

/* 1024px: three columns */
@media (min-width: 1024px) {
  .features__grid { grid-template-columns: repeat(3, 1fr); }
}
```

### Horizontal Scroll → Grid at Breakpoint (Testimonials)

The mechanism that makes cards stay in a single row and overflow:

```css
/* mobile: horizontal scroll */
.testimonials__scroll-wrapper {
  overflow-x: auto;
}

.testimonials__track {
  display: flex;
  width: max-content;  /* track expands to fit all cards side-by-side */
}

/* desktop: switch to grid */
@media (min-width: 1024px) {
  .testimonials__track {
    width: 100%;
    display: grid;
    grid-template-columns: repeat(3, 1fr);
  }
}
```

`width: max-content` is the key — without it, the flex track wraps.

### Fixed Nav Offset

```css
html {
  scroll-padding-top: 72px; /* height of the fixed header */
}
```

Without this, anchor links (`href="#features"`) scroll the target behind the sticky nav.

### Staggered CSS Animation via Inline Custom Properties

```html
<div class="cta-wave-bar" style="--h:20px; --delay:0s"></div>
<div class="cta-wave-bar" style="--h:60px; --delay:.2s"></div>
```

```css
.cta-wave-bar {
  height: var(--h);
  animation: wave-bounce 1.2s ease-in-out var(--delay) infinite alternate;
}

@keyframes wave-bounce {
  from { transform: scaleY(0.3); opacity: 0.5; }
  to   { transform: scaleY(1);   opacity: 1;   }
}
```

Passing per-element values via inline custom properties avoids 12 separate CSS rules.

### Accessible Hamburger Nav

```html
<button class="nav__toggle"
  aria-expanded="false"
  aria-controls="nav-menu"
  aria-label="Toggle navigation menu">
```

```js
toggle.addEventListener('click', () => {
  const open = toggle.getAttribute('aria-expanded') === 'true';
  toggle.setAttribute('aria-expanded', String(!open));
  menu.classList.toggle('nav__menu--open', !open);
});
```

Three attributes together: `aria-expanded` (state), `aria-controls` (links button to menu), `aria-label` (names the button). JS manages state; CSS responds to the open class.

### Nav Without !important

Inverting the media query avoids the `!important` trap:

```css
/* hide only on mobile */
@media (max-width: 767px) {
  .nav__menu { display: none; }
  .nav__menu--open { display: flex; }
}

/* desktop: default is visible — no override needed */
@media (min-width: 768px) {
  .nav__toggle { display: none; }
  .nav__menu { display: flex; flex-direction: row; ... }
}
```

## Accessibility Patterns Applied

| Pattern | Element | Implementation |
|---|---|---|
| Section labels | All `<section>` | `aria-labelledby="section-heading"` |
| Decorative SVGs | Icons, wave, player | `aria-hidden="true" focusable="false"` |
| List semantics preserved | All `<ul>` with `list-style: none` | `role="list"` |
| Social link list | Footer | `<ul role="list">` + `<li>` + `<a>` (not `role="listitem"` on `<a>`) |
| Avatar images | Testimonials | `alt="Photo of NAME"` |
| Star ratings | Testimonials | `aria-label="5 out of 5 stars"` + `aria-hidden` on the emoji |
| Focus ring | Global | `:focus-visible` with `box-shadow` (not `outline: none`) |
| Reduced motion | Global | `@media (prefers-reduced-motion: reduce)` disables all animations |

## Bug Fixed During Review

**`role="listitem"` on `<a>` replaces link semantics.**

```html
<!-- WRONG — screen reader announces as listitem, not a link -->
<div role="list">
  <a role="listitem" href="#">Instagram</a>
</div>

<!-- CORRECT — link semantics preserved -->
<ul role="list">
  <li><a href="#">Instagram</a></li>
</ul>
```

`role` overrides the element's implicit ARIA role. Putting `role="listitem"` on `<a>` removes the link role, so keyboard users can't navigate to it with the link shortcut.

## Review Q&A

**Q: aria-labelledby vs aria-label — when to use which?**
`aria-labelledby` references an existing visible element (points to it by `id`). `aria-label` is for when there's no visible text to reference (icon buttons, landmark disambiguation). Prefer `aria-labelledby` when the label is already on screen — no duplication.

**Q: What makes testimonial cards stay in a single row that overflows?**
`display: flex` (default wraps) + `width: max-content` on the track (forces the track wider than the viewport) + `overflow-x: auto` on the wrapper (enables scroll).

**Q: What are the three arguments to clamp()?**
`clamp(minimum, preferred, maximum)`. The preferred value is usually viewport-relative (e.g. `1rem + 2vw`) so the result scales fluidly between the fixed floor and ceiling.
