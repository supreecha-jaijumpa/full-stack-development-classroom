# 2.5 — Accessibility Basics

> Module: 02 — HTML & CSS · First taught: 2026-06-21 · Last updated: 2026-06-21

## TL;DR
Accessibility is about giving browsers and assistive technology enough information to describe your UI to someone who cannot see it. The browser builds two parallel trees from your HTML: the DOM tree and the Accessibility Tree — only the second is read by screen readers and voice control tools. Every interactive element needs a **role** (what kind of thing it is), a **name** (what it's called), and the correct **state** (enabled, checked, expanded, etc.). Semantic HTML provides all three for free; ARIA is the escape hatch for custom components where native HTML isn't enough.

## Key Concepts

### The Accessibility Tree
When a browser renders a page it builds two parallel structures:

- **DOM tree** — the full HTML with layout and visual information
- **Accessibility tree** — a stripped-down parallel structure that exposes only `role`, `name`, and `state`

Screen readers, voice control software, and keyboard navigation consume the accessibility tree, not the DOM. A visually meaningful element that is absent or unnamed in the accessibility tree is invisible to those users.

```
DOM:   <button class="btn-primary">  <img src="x.svg">  </button>
AT:    role=button   name=???   state=enabled
```

That button has no accessible name. A screen reader announces it as *"button"* with no context.

### Accessible Name Resolution Order
The browser resolves an element's accessible name using this priority order (first match wins):

| Priority | Source | Example |
|----------|--------|---------|
| 1 | `aria-labelledby` | Points to another element's text by ID |
| 2 | `aria-label` | Inline string override on the element |
| 3 | `<label for="id">` | Linked label element for form inputs |
| 4 | Element's own text content | `<button>Submit</button>` |
| 5 | `alt` attribute | `<img alt="Profile photo">` |
| 6 | `title` attribute | Last resort — avoid |

`aria-label` **replaces** the accessible name — it does not append. Use it only when there is no visible text to serve as a name (icon-only buttons, search inputs with a magnifying glass icon, etc.).

### Form Labels
Every input needs a programmatically associated label. Three patterns:

```html
<!-- 1. Explicit label (preferred) — for/id link -->
<label for="email">Email</label>
<input type="text" id="email">

<!-- 2. Wrapped label — no for/id needed -->
<label>
  Email
  <input type="text">
</label>

<!-- 3. aria-label — when no visible label is possible -->
<input type="search" aria-label="Search repositories">
```

`placeholder` is NOT a label — it disappears when the user types and is not reliably announced by all screen readers. A form field with only a placeholder has no accessible name when focused.

### Keyboard Navigation
Everything a mouse user can click must be reachable by Tab and operable with Enter or Space.

**Native HTML — keyboard-focusable by default:**
`<a href>`, `<button>`, `<input>`, `<select>`, `<textarea>`

**Not focusable by default:**
`<div>`, `<span>`, `<p>`, and most other elements

Using `<div onclick="...">` instead of `<button>` is an accessibility bug — it is not in the tab order and has no built-in keyboard event handling. The fix is to use a `<button>`, or if the element cannot change, add `role="button" tabindex="0"` and keyboard event handlers (always prefer the native element).

| `tabindex` value | Behaviour |
|-----------------|-----------|
| `tabindex="0"` | Adds the element to the natural tab order |
| `tabindex="-1"` | Focusable via `element.focus()` in JS, but not reachable by Tab |

### Focus Styles and `:focus-visible`
```css
/* WRONG — removes the only visual location signal for keyboard users */
*:focus { outline: none; }

/* CORRECT — hides ring on mouse click, keeps it for keyboard navigation */
*:focus:not(:focus-visible) { outline: none; }
*:focus-visible {
  outline: 2px solid #your-brand-color;
  outline-offset: 2px;
}
```

`:focus-visible` fires only when the browser determines focus arrived via keyboard (Tab, arrow keys, etc.). Mouse clicks on buttons do not trigger it — so mouse users never see the ring, and keyboard users always do.

Removing `outline: none` globally without `:focus-visible` is one of the most common and most harmful accessibility bugs in production frontends.

### Color Contrast (WCAG AA)
| Context | Minimum ratio |
|---------|--------------|
| Normal text (< 18px regular or < 14px bold) | 4.5 : 1 |
| Large text (≥ 18px regular or ≥ 14px bold) | 3 : 1 |
| UI components (borders, icons, input outlines) | 3 : 1 |

White on white = 1:1 (invisible). Black on white = 21:1 (maximum).

Never communicate information through color alone — pair every color signal with a secondary indicator (icon, text, or pattern):

```html
<!-- Bad: color is the only error signal -->
<input style="border-color: red">

<!-- Good: color + icon + text + programmatic association -->
<input aria-describedby="email-error">
<span id="email-error">⚠ Email is required</span>
```

`aria-describedby` wires the error message into the input's accessible description — screen readers announce it after the label and role.

### ARIA — When to Use It
ARIA (Accessible Rich Internet Applications) exists for one reason: when native HTML semantics are not enough to describe a custom UI component.

**The first rule of ARIA: don't use ARIA if native HTML can do it.**

| Native HTML | Don't replace with ARIA |
|-------------|------------------------|
| `<nav>` | `<div role="navigation">` |
| `<button>` | `<div role="button" tabindex="0">` |
| `<main>` | `<div role="main">` |
| `<img alt="...">` | `<div role="img" aria-label="...">` |

Common ARIA attributes and their purpose:

| Attribute | Purpose |
|-----------|---------|
| `aria-label` | Overrides / provides the accessible name |
| `aria-labelledby` | Points to another element as the name source |
| `aria-describedby` | Points to a description element (e.g., error message) |
| `aria-hidden="true"` | Removes element and its children from the accessibility tree |
| `role` | Assigns or overrides the semantic role |

### `aria-hidden` for Decorative Content
Emoji and icon characters are announced by screen readers using their Unicode name, which can be verbose and confusing:

```html
<!-- Screen reader: "house building, Home, link" -->
<a href="#">🏠 Home</a>

<!-- Screen reader: "Home, link" -->
<a href="#"><span aria-hidden="true">🏠</span> Home</a>
```

`aria-hidden="true"` removes the element and all its children from the accessibility tree. Use it on decorative SVGs, icon fonts, and emoji where surrounding text already provides the label.

## Diagrams

### Name Resolution Decision Tree
```
Does the element have aria-labelledby? → use that text
  ↓ no
Does it have aria-label? → use that string
  ↓ no
Is it a form input with a <label for="id">? → use label text
  ↓ no
Does it have readable text content? → use that text
  ↓ no
Does it have an alt attribute (img)? → use alt text
  ↓ no
→ No accessible name — screen reader announces role only ("button", "link")
```

## Common Pitfalls

- **Removing focus outlines globally** (`*:focus { outline: none }`) kills keyboard navigation for every user. Use `:focus-visible` to control when the ring appears instead.
- **Using `placeholder` as a label** — placeholder disappears on input, is not reliably announced, and often fails contrast requirements (typically grey on white).
- **`aria-label` on elements with existing visible text** — `aria-label` replaces the accessible name, which creates a mismatch between what is visible and what is announced. Correct use is on elements with no readable text at all.
- **Role or `aria-label` without keyboard operability** — a `<div role="button">` with no `tabindex="0"` is announced as a button but unreachable by keyboard. Accessibility attributes and keyboard support must be added together.
- **Communicating state with color only** — color blindness affects approximately 8% of men. Always pair color with a secondary signal (icon, text, pattern).
- **Nesting interactive elements** — `<a>` inside `<button>` or `<button>` inside `<a>` is invalid HTML and produces unpredictable screen reader output.
