# 2.3 — Layout: Flexbox & Grid

> Module: 02 — HTML & CSS · First taught: 2026-06-19 · Last updated: 2026-06-19

## TL;DR

Flexbox is a one-dimensional layout model — you control one axis at a time (row or column). CSS Grid is two-dimensional — the container owns rows and columns simultaneously. `fr` units express a fraction of the available space left after fixed-size tracks and gaps are subtracted. Grid items default to `min-height: auto`, which lets them grow beyond their track size; adding `min-height: 0` restores the constraint and is required before `overflow-y: auto` can trigger internal scroll.

---

## Key Concepts

### Flexbox vs Grid — 1D vs 2D

The useful mental model is **how many axes the container controls**:

| Model | Axes | Reach for it when… |
|-------|------|---------------------|
| Flexbox | 1 — row **or** column | items flow along one axis; alignment on the cross axis is incidental |
| Grid | 2 — rows **and** columns | placement decisions live on both axes simultaneously |

A nav bar → Flexbox. A page shell (header / sidebar / main / footer) → Grid.

"Flexible vs fixed" is a common shortcut but it misleads: both models can be flexible or fixed. The axis count is the deciding factor.

### `fr` units — fraction of available space

`fr` is calculated in two steps:

1. The browser assigns all fixed-size tracks (`px`, `rem`, `min-content`, etc.) and subtracts all `gap` values.
2. The remainder is divided proportionally among `fr` tracks.

```css
grid-template-columns: 200px 1fr 1fr;
/* container: 620px, gap: 20px (two gaps = 40px) */
/* available = 620 - 200 - 40 = 380px */
/* each 1fr = 190px */
```

`%` doesn't participate in gap arithmetic — you'd need `calc((100% - 200px - 40px) / 2)` to get the same result. `fr` does the math for you.

### `min-height: auto` — the default that bites

Every grid item defaults to `min-height: auto`. This means: **the item refuses to shrink below its content height**, even when its track says `1fr`.

```css
.shell {
  display: grid;
  height: 100vh;
  grid-template-rows: 60px 1fr;
}

.main {
  overflow-y: auto; /* won't work yet */
}
```

`.main` sits in a `1fr` row. Its content is 2000px tall. `min-height: auto` says it must be at least 2000px — so it overflows `100vh`, and `overflow-y: auto` never triggers because `.main` is taller than its container.

**Fix:** `min-height: 0` opts the item out of the auto minimum, letting the track constraint win.

```css
.main {
  overflow-y: auto;
  min-height: 0; /* ← lets 1fr actually constrain the item */
}
```

The same rule applies to Flexbox children — use `min-height: 0` (or `min-width: 0` for horizontal overflow) when a flex item needs to be smaller than its content.

### Fixed tracks don't need the fix

A fixed track (`60px`, `200px`, `4rem`) is an absolute ceiling. Even with `min-height: auto`, the browser forces the item into exactly that size. Only flexible tracks (`fr`, `auto`, `min-content`) are negotiated — and only negotiated tracks can be overridden by `min-height: auto`.

Rule of thumb: **`min-height: 0` is needed on grid items in `fr` or `auto` rows when you need overflow or scroll.**

### CSS selector scope

When the same HTML element type appears in multiple layout contexts, bare element selectors apply to all of them:

```css
/* Intended for header nav — but applies to EVERY nav */
nav { display: flex; gap: 24px; }

/* Intended for sidebar — overwrites the rule above for EVERY nav */
nav { flex-direction: column; gap: 8px; padding: 24px 16px; }
```

Fix: qualify with a parent selector, or add a class.

```css
header nav { gap: 24px; }
.sidebar  { flex-direction: column; gap: 8px; padding: 24px 16px; }
```

## Examples

### App shell — page shell that never scrolls

```css
body {
  display: grid;
  height: 100vh;
  grid-template-rows: 60px 1fr;
  overflow: hidden; /* belt-and-suspenders */
}

.shell-body {
  display: grid;
  grid-template-columns: 180px 1fr;
  min-height: 0; /* lets 1fr row stay within 100vh */
}

main {
  overflow-y: auto;
  min-height: 0; /* lets 1fr column constrain main's height */
}
```

```html
<body>
  <header>…</header>
  <div class="shell-body">
    <nav class="sidebar">…</nav>
    <main>…long content…</main>
  </div>
</body>
```

### Flexbox header — logo / nav / avatar

```css
header {
  display: flex;
  align-items: center;
  justify-content: space-between;
  padding: 0 24px;
}
```

Three children: logo (left), nav (center), avatar (right). `space-between` pushes the first child to the start edge and the last to the end edge, distributing remaining space between them.

### Card gallery — 3 columns, auto rows

```css
.card-grid {
  display: grid;
  grid-template-columns: repeat(3, 1fr);
  gap: 16px;
}
```

`repeat(3, 1fr)` is shorthand for `1fr 1fr 1fr`. Rows are created implicitly as cards are added — you only need to declare columns.

## Diagrams

### The `min-height: 0` chain in a nested grid

```
body  [height: 100vh, display: grid, rows: 60px 1fr]
│
├── header  [fixed 60px — no fix needed]
│
└── .shell-body  [1fr row — needs min-height: 0]
    [display: grid, columns: 180px 1fr]
    │
    ├── nav.sidebar  [180px column — no fix needed, height from stretch]
    │
    └── main  [1fr column — needs min-height: 0 + overflow-y: auto]
```

Each `1fr` node in the chain needs `min-height: 0`. Fixed nodes don't.

## Common Pitfalls

- **Reaching for Flexbox for 2D layouts.** A sidebar + main layout tempts Flexbox because "it's just two items side by side." But as soon as the header and footer are added, you're placing things on two axes — Grid is the right tool.

- **Confusing `fr` with `%`.** `1fr` in `grid-template-columns: 200px 1fr` is not `100% - 200px`. It's `(container - 200px - gaps) × 1`. `%` doesn't subtract gap; `fr` does.

- **Adding `overflow-y: auto` without `min-height: 0`.** The overflow property is set, the layout looks right in DevTools, but scrolling doesn't work. The item is still taller than the viewport because `min-height: auto` is winning. `min-height: 0` must come first.

- **One `nav` rule clobbering another.** When a page has both a header nav and a sidebar nav, bare `nav` selectors apply to both. The second rule in source order wins. Always scope to a parent or use a class.

- **Assuming `overflow: hidden` on the body is the real fix.** It hides the symptom (outer scroll) but the layout is still broken — the grid item is taller than `100vh`, it's just clipped. `min-height: 0` is the correct fix.

## Quick Recall

1. You're building a layout with a fixed header, a left sidebar, and a scrollable main area. Which layout model do you use for the outer shell? Why?

2. `grid-template-columns: 300px 1fr 2fr` in a `900px` container with `gap: 30px` between columns. How wide is `2fr`?

3. You add `overflow-y: auto` to a grid item inside a `1fr` row, but the item doesn't scroll. What's the most likely missing declaration?

4. Why does a fixed `60px` row not need `min-height: 0`, while a `1fr` row does?

5. You have two `<nav>` elements — one in the header, one in a sidebar. Your CSS has `nav { flex-direction: column; }`. What breaks, and how do you fix it?

<details>
<summary>Answers</summary>

1. Grid — the placement decisions live on two axes (row and column simultaneously). Flexbox only controls one axis at a time.
2. Available = 900 - 300 - 60 (two gaps) = 540px. `1fr` = 180px, `2fr` = 360px.
3. `min-height: 0` — without it, `min-height: auto` lets the item grow past its track, and `overflow-y: auto` never activates.
4. Fixed tracks (`60px`) enforce an absolute ceiling regardless of content size. Flexible tracks (`fr`) are negotiated — `min-height: auto` can override them.
5. Both navs get `flex-direction: column`. Fix: scope the rule — `header nav { … }` and `.sidebar { … }`, or add distinct classes.

</details>
