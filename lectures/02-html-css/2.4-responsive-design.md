# 2.4 — Responsive Design

> Module: 02 — HTML & CSS · First taught: 2026-06-19 · Last updated: 2026-06-19

## TL;DR

Responsive design makes a single HTML file adapt gracefully to any viewport width. The four tools that do most of the work are: the viewport meta tag (tells mobile browsers to use real pixel width), mobile-first media queries (`min-width`), `auto-fit` + `minmax()` for breakpoint-free grids, and `clamp()` for fluid sizing between a floor and ceiling.

## Key Concepts

### The Viewport Meta Tag

Without this line, mobile browsers lie to your page:

```html
<meta name="viewport" content="width=device-width, initial-scale=1">
```

When smartphones first appeared, all websites were desktop-only — fixed 980px+ layouts. So mobile browsers invented a trick: pretend the screen is 980px wide, render the full desktop layout, then zoom it out to fit. This is still the **default** today.

The result: a phone physically 390px wide tells your CSS "I'm 980px wide." Your `@media (max-width: 600px)` rules never fire. The entire page renders as a tiny desktop layout.

`width=device-width` overrides the simulation — use the actual physical pixel width.  
`initial-scale=1` prevents the browser from applying an initial zoom offset on page load.

### Mobile-First vs Desktop-First

**Mobile-first** (`min-width`): write the base CSS for mobile, then layer in complexity as the viewport grows.

```css
/* base: single column */
.card { display: block; }

/* at 768px+: two columns */
@media (min-width: 768px) {
  .card { display: grid; grid-template-columns: 1fr 1fr; }
}
```

**Desktop-first** (`max-width`): write the full-featured layout first, strip it away for small screens.

```css
/* base: two columns */
.card { display: grid; grid-template-columns: 1fr 1fr; }

/* below 768px: single column */
@media (max-width: 767px) {
  .card { display: block; }
}
```

Both produce the same visual output. The practical difference: mobile CSS is simpler (smaller fonts, single columns, no complex grids). Mobile-first means that simple CSS is the base that loads everywhere — media queries only *add* complexity. Desktop-first means the heavy CSS always loads first and then gets stripped down.

### `auto-fit` + `minmax()` — Responsive Grids Without Breakpoints

```css
grid-template-columns: repeat(auto-fit, minmax(250px, 1fr));
```

- `minmax(250px, 1fr)` — each column is at least 250px, but grows to fill available space
- `auto-fit` — create as many columns as fit without going below 250px; collapse empty tracks

At 300px wide → 1 column. At 600px → 2 columns. At 900px → 3 columns. No media queries needed.

**`auto-fill` vs `auto-fit`:**
- `auto-fill` keeps empty ghost tracks (columns exist even if no item fills them)
- `auto-fit` collapses empty tracks so filled columns stretch to cover the full row

For card grids, always use `auto-fit`.

### `clamp()` — Fluid Sizing

```css
font-size: clamp(min, preferred, max);
```

The value grows with the viewport (via `vw`), clamped between a floor and ceiling:

```css
font-size: clamp(0.9rem, 2vw, 1.1rem);
```

| Viewport | `2vw` resolves to | Result |
|----------|-------------------|--------|
| 320px | 6.4px | Clamped up to `0.9rem (14.4px)` |
| 700px | 14px | Sits in range, uses `14px` |
| 1440px | 28.8px | Clamped down to `1.1rem (17.6px)` |

Works equally well for padding, gap, and any length property:

```css
padding: clamp(1rem, 4vw, 3rem);
gap: clamp(0.5rem, 2vw, 1.5rem);
```

### Hiding Elements on Mobile

```css
/* mobile: hidden */
aside { display: none; }

/* 768px+: show */
@media (min-width: 768px) {
  aside { display: flex; }
}
```

When a sidebar is hidden, its grid track should also collapse:

```css
/* mobile: single column */
.layout { grid-template-columns: 1fr; }

@media (min-width: 768px) {
  /* restore sidebar + main */
  .layout { grid-template-columns: 180px 1fr; }
}
```

If you hide the sidebar but leave `grid-template-columns: 180px 1fr`, the 180px track still occupies space even with no visible content.

## Common Pitfalls

**Forgetting the viewport meta tag.** Mobile-first media queries appear to have no effect because the browser reports a fake 980px viewport. The fix is always the same one tag in `<head>`.

**Hiding an element but not its grid track.** `display: none` removes the element from layout, but a fixed-size grid track (`180px`) keeps its reserved space. Always set the parent's `grid-template-columns` alongside `display: none`.

**Using `minmax()` in a container that's too narrow.** `minmax(200px, 1fr)` in a 140px-wide container can't fit even one column at minimum size — it overflows. Make sure the container has room for at least one column before relying on `auto-fit`.

**Confusing `auto-fill` and `auto-fit`.** `auto-fill` leaves ghost columns that prevent remaining items from stretching. For card grids, `auto-fit` is almost always correct.

**Setting `initial-scale` without `width=device-width`** (or vice versa). Some older browsers still apply zoom without both values. Use both together.
