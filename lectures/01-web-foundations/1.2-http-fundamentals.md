## HTTP Message Shape

HTTP is just text. Every exchange is a request + response pair with the same structure:

**Request:**
```
[METHOD] [PATH] HTTP/1.1
Host: api.github.com
Authorization: Bearer <token>
Content-Type: application/json
                              ← blank line
{ "body": "optional" }
```

**Response:**
```
HTTP/1.1 200 OK
Content-Type: application/json
Cache-Control: public, max-age=60
                              ← blank line
{ "data": "..." }
```

---

## HTTP Methods

| Method | Intent | Body? | Safe | Idempotent |
|--------|--------|-------|------|------------|
| GET | Read | No | ✅ | ✅ |
| POST | Create / trigger | Yes | ❌ | ❌ |
| PUT | Replace (full) | Yes | ❌ | ✅ |
| PATCH | Update (partial) | Yes | ❌ | ❌* |
| DELETE | Remove | No | ❌ | ✅ |

- **Safe** = no server side effects
- **Idempotent** = 10 calls = same result as 1 call

## Status Code Families

```
2xx → success
  200 OK, 201 Created, 204 No Content

3xx → redirect
  301 Moved Permanently, 302 Found, 304 Not Modified

4xx → client error
  400 Bad Request, 401 Unauthorized, 403 Forbidden
  404 Not Found, 422 Unprocessable, 429 Too Many Requests

5xx → server error
  500 Internal Server Error, 502 Bad Gateway, 503 Unavailable
```

**401 vs 403:** 401 = not authenticated (send to login). 403 = authenticated but not allowed (show "access denied").

## Key Headers

**Request:**
- `Content-Type: application/json` — body format
- `Accept: application/json` — desired response format
- `Authorization: Bearer <token>` — auth
- `Cookie: ...` — sent automatically by browser

**Response:**
- `Content-Type` — response body format
- `Set-Cookie: ...; HttpOnly; Secure` — set browser cookie
- `Cache-Control` — caching instructions
- `Location: /resource/42` — used with 201/3xx

---

## Cache-Control: public vs private

```
Cache-Control: public, max-age=60, s-maxage=60
```

- `max-age` — browser (private) cache duration in seconds
- `s-maxage` — shared cache (CDN) duration in seconds
- `public` — CDN is allowed to cache this for all users
- `private` — browser only, CDN must not cache

**Security bug:** `Cache-Control: public` on `/api/me` lets the CDN serve one user's profile to another user. Fix: `Cache-Control: private, no-cache`.

**Rule:** user-specific data → `private`. Shared/public data → `public` with appropriate `max-age`.

---

## Rate Limiting Headers

`X-RateLimit-Remaining: 58` — server signals how many requests you have left before hitting the limit. A well-built client reads this and self-throttles rather than waiting for a `429`.

---

## Statelessness

HTTP has no memory. Every request is self-contained — the server starts from zero each time.

**Constraint:** auth context must travel with every request (token or cookie).

**Feature:** any server can handle any request → horizontal scaling works. No sticky sessions needed. This is why Netflix, GitHub, etc. can run thousands of instances behind a load balancer.

Auth is added back on top of statelessness via:
- **Cookies** — server sets, browser sends automatically
- **Bearer tokens** — client stores, attaches manually as `Authorization` header
